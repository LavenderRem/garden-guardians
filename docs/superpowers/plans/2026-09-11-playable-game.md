# 庭院守卫可玩首版实现计划

> 执行方式：使用 writing-plans 与 subagent-driven-development 技能拆分独立素材任务；主任务负责战斗和界面集成，完成后独立审查。用户已授权继续实现。

**目标：** 在现有原创庭院与精灵素材基础上交付能从菜单玩到结算的三关浏览器游戏。

**架构：** TypeScript 战斗模型管理固定步长、资源、单位和波次；Phaser 负责画面与输入。原生 HTML 管理菜单、种子卡和设置，保持中文清晰且支持键盘。媒体预先制作，运行时不调用生成服务。

**技术栈：** Phaser 4.2.1、TypeScript、Vite、Vitest、本地 PNG/WebP/WAV。

**规格来源：** `docs/2026-09-07-game-roadmap.md`；已确认素材和 `docs/2026-09-08-motion-samples.md`。

## 全局约束与执行取舍

- 1280 × 720 逻辑画布，5 行 × 9 列；桌面浏览器优先，页面随窗口缩放。
- 四种植物、三种敌人、三关；包含铲除、救场、暂停、重开、音量和解锁存档。
- 沿用暖橙、苔绿、墨绿、奶油白视觉，角色不复用原作资源。
- 当前目录不是 Git 仓库，直接在指定项目目录实现，不额外迁移素材或创建工作树。
- 首版关卡缩短为约 2 分钟，便于快速试玩。片头与实机视频不阻塞战斗实现；本轮媒体交付以已完成动画与新增声音为基础。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `src/game/content.ts` | 单位数值、关卡出怪时间与棋盘坐标 |
| `src/game/model.ts` | 独立模拟与动作校验 |
| `src/game/model.test.ts` | 资源、战斗、波次、暂停和胜负的实际规则测试 |
| `src/game/scene.ts` | 背景、角色动画、投射物、交互和反馈 |
| `src/main.ts`、`src/style.css` | 菜单、卡片、进度、暂停和结算 |
| `src/save.ts`、`src/save.test.ts` | 版本化本地存档及容错验证 |
| `src/audio.ts` | 播放原创声音、音量和背景音乐 |
| `scripts/create_audio.py` | 可复现的原创音乐和音效制作 |
| `public/assets/` | 实际加载的发行素材 |

## 任务与验收

1. [x] 战斗模型：先写种植扣费、非法格子、冷却、暂停、分行命中、一次救场和最终清场测试，运行观察失败；实现最小规则后再跑通过。以 `new Battle(level)`、`plant(type,row,col)`、`advance(seconds)`、`collect(id)`、`remove(row,col)` 为接口。
2. [x] 原创音频：独立制作 12 个短音效、2 段循环配乐和胜负短乐。输出 WAV 与中文清单，验证样本数、峰值和循环末端。
3. [x] 视觉集成：复制现有庭院和三张动画表，补充三株静态植物；统一透明边缘、脚底位置和卡片缩略图。画布显示模型状态，种植使用同一坐标映射。
4. [x] 游戏流程：实现开始、选关、说明、暂停、继续、重开、返回庭院、结果解锁与音量；本地存档损坏或不可写时仍可玩。
5. [x] 验证交付：单元测试通过、TypeScript 与生产构建通过；浏览器实际操作种植、采集、铲除、暂停与重开，检查不同窗口尺寸和控制台。独立审查后修复问题，补充中文启动说明和本轮验收记录。
